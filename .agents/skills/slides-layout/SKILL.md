# Slides layout — 内部の配置設計

通常の入口は [slides-create](../slides-create/SKILL.md)。ユーザーにこのスキルの追加指定を求めない。
呼び出し元から、メッセージ、説明文、聴衆と用途、寸法と文字サイズ、使用可能な図表を受け取る。
まず `docs/MESSAGE_FIRST.md` の配置仕様を読む。

## 設計前に確認すること

文章だけを読んで「なぜ次の主張が必要か」を説明できることを確認する。
用語が未定義、目的と要素技術が同列、結果が何を検証したか不明、といった問題は
配置で隠さず呼び出し元へ返す。既に十分なメッセージや既存配置がある場合は再分析を省く。

新規の構成は、文章と概念の導入順を決めた後にAstraへ設計を依頼する。
依頼には文章・図表・条件を渡し、研究上の主張を独自に増やさせない。
利用できない場合はその事実を記録し、利用可能な手段で設計する。

## 配置する

- 各領域がどの段落の主張を担い、図が説明・裏付けるのは何かを明記する。
- 読む順序は概念の導入順に合わせる。前提、提案、要素技術、証拠などの関係を
  大きさ・近さ・従属関係に反映する。均等な箱や対称性を目標にしない。
- 提供された図表の比率と図中文字の大きさ、実際の文章量を考慮して領域を予約する。
  主張が重要でも数値を巨大に繰り返すだけでは面積の根拠にならない。
- 視認距離に必要な文字サイズを先に決める。用紙寸法、拡大印刷、本文・図中ラベルを
  個別に考える。すべての資料に同じサイズや列数を固定しない。
- 長い説明を図へ置換する前に、その図が何を理解させるかを決める。概念を説明する
  具体例を使い、研究内容と無関係な装飾や架空の結果を追加しない。

`story.yaml` に対応する `layout.yaml` を作る。ページ、領域、読む順序、段落・図表ID、
面積を割く理由を記録する。CLIは宣言された順序と幾何を検査するが、意味の良し悪しは判断しない。

```bash
structured-slide-creator story check story.yaml
structured-slide-creator layout check layout.yaml
structured-slide-creator layout md layout.yaml --out layout.md
structured-slide-creator layout build layout.yaml --out poster_layout.pptx --theme academic
structured-slide-creator review poster_layout.pptx --sources story.yaml layout.yaml
```

ワイヤフレームには短い領域ラベル、予定する図表ID、必要な読み順だけを表示する。
実画像・本文・結果の数値はまだ入れない。原稿の図表が手元になくても予約枠は作れる。
配置案を実際に描画し、できた画像をAstraに確認してもらう。主要な領域、余白、読む順序、
図と文章の収まりの見通しを評価する。プレースホルダが収まることを、実文章の適合と混同しない。

呼び出し元へ、配置案PPTX、説明Markdown、layout YAML、確認結果を返す。
配置だけの依頼ならそこで完成。内容まで依頼されている場合は `slides-create` が制作を続ける。
